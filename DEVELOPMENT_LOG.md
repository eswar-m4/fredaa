## Architecture Decisions

### 1. **Modular Structure**
```
app/
├── core/      # Shared utilities (logging, errors, constants)
├── models/    # Data validation (Pydantic schemas)
├── services/  # Business logic layer
└── api/       # HTTP endpoints
```
**Rationale**: Separation of concerns makes the codebase scalable and testable. Each layer has clear responsibility.

### 2. **Configuration Management**
- Used `Pydantic` with `BaseSettings` for type-safe configuration
- Loads from `.env` file following 12-factor app methodology
- Allows easy environment switching (dev/prod)

### 3. **Logging Strategy**
- **Console Handler**: Real-time visibility during development
- **File Handler**: Production audit trail with automatic rotation
- **Structured Format**: Consistent timestamp, level, and module tracking

### 4. **API Design**
- REST endpoints with clear versioning (`/api/v1/`)
- Comprehensive error responses with error codes
- OpenAPI documentation auto-generated by FastAPI
- Input validation using Pydantic models

### 5. **Phase 1 Upload Service**
- **In-memory storage**: Simple for Phase 1, will use database in Phase 2+
- **Metadata validation**: File size and name checks only
- **Format detection**: Simple extension-based detection
- **Skeleton ready**: Methods prepared for Phase 2 parsing integration

## Architecture Decisions

### 1. **Gemini Flash Provider Abstraction**
- Abstracted through `AIUnderstandingService` and `AIProvider`
- Configuration-driven (`GEMINI_API_KEY` from environment)
- Easy to swap providers by implementing the same `AIProvider.generate()` contract
- No hardcoded keys anywhere

### 2. **Unified Output Schema**
Every input normalizes to `ProcessedInput`:
- `input_type`: Source type (text, csv, xlsx, pdf, docx, txt)
- `entity_type`: Inferred classification (company, person, email, url, etc.)
- `raw_input`: Original user input
- `content`: Extracted/processed content
- `normalized_data`: Structured attributes
- `confidence_score`: 0.0-1.0 confidence metric
- `attributes`: Key-value pairs extracted by AI
- `metadata`: Additional processing info
- `processing_time_ms`: Performance metrics

### 3. **Two Endpoint Pattern**
- `/process-input`: Raw text input (simplicity)
- `/process-file`: File upload + parsing + AI analysis (completeness)
- Both use same underlying AI service

### 4. **Parser Integration**
- If file input, use existing Phase 2 parser engine
- For tabular data (CSV/XLSX), extract columns as content
- For text data (PDF/DOCX/TXT), use text preview
- Parser results attached to metadata

### 5. **Prompt Strategy**
- Generic, industry-independent prompts
- Asks AI to classify, extract attributes, and provide confidence
- Structured JSON response format
- Temperature set to 0.3 for consistency

### 6. **Error Handling Layers**
1. File validation (size, format)
2. Parser errors (invalid file format)
3. API connection errors (network issues)
4. API errors (quota, invalid key)
5. JSON parsing errors (malformed response)
